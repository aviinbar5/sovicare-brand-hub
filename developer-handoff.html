Anatomy of every page section מה יש בכל סקשן עמוד

1 · Design

Desktop 1440 + Mobile 390

The page itself. Each block is a named frame, numbered in reading order (01 Header, 02 Hero …). Section links below jump to each block.

2 · Pins

Numbered magenta pins

Pins sit on the design and are named annotation pin · hide for hand-off. They are not part of the UI. Each number matches a row in the Interactions spec.

3 · Spec

Interactions spec (760 wide)

One per breakpoint. For each numbered block: hover, click, scroll, focus, mobile behaviour, durations, and a live Figma Motion demo you can play.

4 · Annex

Annex · Interaction states

Static drawings of every state (default, hover, selected, open, error, sticky). Build these exactly; they are the visual contract for states.

5 · Guides

📘 Guides column

Explanation notes to the left of each section, in a blue outline. Read them; never build them.

6 · Dev Mode

Annotations on every frame

Each desktop and mobile frame carries a Dev Mode note pointing to its spec and annex. Colours are bound to variables and text to text styles, so Dev Mode shows token names.

Recommended build order

Build the system first, then the pages.

The site is a small number of shared parts arranged many times. Building those parts first makes every page after the first one fast and consistent.

האתר בנוי ממעט חלקים משותפים שחוזרים הרבה פעמים. בונים קודם את החלקים, ואז כל עמוד אחרי הראשון מהיר ואחיד.

Tokens · טוקנים

Export the Figma variables to CSS custom properties: Primitives, Color (semantic), Spacing, Radius, Size, and the three-mode Category theme. Map the 21 text styles to type classes or utilities. Components only use semantic tokens, never primitives. See Foundations.

Global shell · מעטפת

Header (desktop + mobile menu), Footer, Legal band, and the Header-on-scroll state (after 8px the header turns Deep Teal, 220ms). These appear on every page. Components: Header / Desktop, Header / Mobile, Footer / Desktop, Footer / Mobile, Legal Band / Desktop.

Core components · רכיבים

Button (24 variants: Label, Style, State, Size), Icon Button, Text Link, Chip, Eyebrow, Section Head, Mark and Logo, Trust Item, FAQ Row (accordion), Step Row, Category Card, Goal Card, Quote Card, Channel Card. Build their states from the annexes, and their motion from the Motion tab.

Homepage · עמוד הבית

Proves the shell, sections, stories carousel, how-it-works, FAQ and the first-question block. Check desktop and mobile against both specs before moving on.

Category template · תבנית קטגוריה

One template, three themes: Better Intimacy, Longevity, Hair Loss. Switch the Category theme mode, not the components. Includes the modular product cards (desktop set 2267:573, mobile set 2267:6458) with their optional price line, facts, note and guide link.

Product templates · תבניות מוצר

Build the PDP template once (gallery, buy box, plan selection, sticky buy bar, in-page nav, modules, ISI) and the Product guide template once (guide hero, at a glance, on this page, sticky CTA bar, ISI). Then fill 10 PDPs and 8 guides from data. See Products.

Content pages · עמודי תוכן

How It Works, Contact (form states), FAQ (filters + accordion), Telehealth Notice and Terms of Service (sticky contents + scroll-spy).

Motion, accessibility, QA · תנועה, נגישות, בדיקות

Apply the motion tokens, add reduced-motion fallbacks, keyboard paths and focus states, then run the QA checklist on real devices.

The right way to work הדרך הנכונה

  • Read in this order: design frame → Interactions spec → Annex → Guides column.
  • Use Dev Mode. Colours show variable names and text shows style names. If you see a raw hex value in a design frame, ask: only annotation colours are unbound on purpose.
  • Theme by data attribute. For example <body data-category="longevity"> switches every theme/* token. Never hard-code category colours.
  • Content as data. Products, prices, FAQs, reviews, safety text and legal copy belong in a CMS or data files. Many of today's values are illustrative.
  • Mobile is its own design. Section order, carousels and sticky bars differ. Do not let mobile fall out of desktop CSS by accident.
  • Between 390 and 1440 there is no tablet frame. Keep the 1180 max content width and let layouts reflow; agree breakpoints with the design owner.
  • סדר קריאה: מסגרת העיצוב ← פאנל האינטראקציות ← הנספח ← עמודת ההסברים.
  • עובדים עם Dev Mode. הצבעים מציגים שמות משתנים והטקסטים מציגים שמות סגנונות. ערך hex גולמי במסגרת עיצוב – שואלים.
  • ערכת נושא לפי attribute. מחליפים קטגוריה דרך data-category ולא מקודדים צבעים.
  • תוכן כנתונים. מוצרים, מחירים, שאלות, ביקורות, טקסט בטיחות וטקסט משפטי – מ‑CMS או מקבצי נתונים.
  • מובייל הוא עיצוב בפני עצמו. סדר הסקשנים והפסים הצפים שונים.
  • בין 390 ל‑1440 אין מסגרת טאבלט. שומרים על רוחב תוכן מקסימלי 1180 ומסכמים נקודות שבירה מול בעלת העיצוב.

    Motion and interaction · SoviCare + Motion lab
    
Every animation, transition and state change.

    
One catalogue for the 17 SoviCare patterns in Figma, the Motion lab, and the Codex page demos in the Interaction & Motion gallery. Each row says what triggers it, how long it takes, where it is used, and where to watch it live.

    
קטלוג אחד שמאחד את 17 הדפוסים שבפיגמה ואת הדמואים מה‑Motion lab. לכל שורה: טריגר, משך, איפה זה בשימוש ואיפה רואים את זה חי.

  

  

    
The rule
Motion confirms, it never performs. UI states use one easing and four durations; brand shapes get a longer, expressive entrance only in heroes and closing CTAs.
התנועה מאשרת פעולה ולא מופיעה בשביל הרושם.

    
UI state tokens

      
press140ms--motion-press

      
hover · select180ms--motion-fast

      
open · slide220ms--motion-base

      
reveal · reorder320ms--motion-slow

      
Easing ease. Rise distance 10px. Selection = 1.02 scale + border. Reveal plays once per visit.

    
Brand-shape tokens

      
pivot820ms
wipe520ms
rise620ms
shift520ms

      
Easing cubic-bezier(.22,1,.36,1). Hero copy staggers 120ms. Inside content, kit pieces use the shorter pivot 320ms + wipe 620ms.

  

  
Reconciled from two sources.The Figma library uses ease and 140–320ms. The Motion lab adds an expressive curve and longer brand-shape moves. Use both, each in its own place: UI states with the SoviCare tokens, decorative brand shapes with the Motion lab curve. שני המקורות אוחדו: מצבי ממשק לפי טוקני SoviCare, וכניסת צורות המותג לפי ה‑Motion lab.

Reduced motion and accessibility נגישות ותנועה מופחתת

    
    
      
  • With prefers-reduced-motion: reduce, every state appears instantly and smooth scroll becomes a jump.
    • 
      
  • Count-up stats show the final number; carousels do not auto-advance.
    • 
      
  • Tabs (How It Works) support arrow keys, Home and End; accordions use aria-expanded; chips and plans use aria-pressed / role="radio".
    • 
      
  • The sticky bar is inert and aria-hidden while hidden.
    • 
      
  • Focus is always visible (3px outline). Tap targets are at least 44px.
