UX patterns.

How the components behave once a real person is using them. Every pattern here holds for both questionnaire systems unless it says otherwise.

Hub Foundations Components

The
boundary

One rule governs everything on this page: the assessment routes, the questionnaire qualifies. Nothing that qualifies appears in the assessment; nothing that routes appears in the questionnaire.

Question
screen

One question owns the screen. The question is the headline — never a second headline above it, never a section label competing with it.

Adaptive
branch

A branch is data, not a design. It swaps the answer set and may insert microsteps — it never introduces a new layout, a new colour, or a visible change in the progress count.

Deep
intake

The eligibility questionnaire inverts almost every assessment rule, deliberately. It looks like work because it is work, and the user should be able to feel that they are now in a clinical process.

Consent
and privacy

Consent is its own step, never a checkbox bolted to a submit button. Each acknowledgement is separate, unticked by default, and none is pre-selected.

End
states

Four ways a flow can end. None of them is a failure, none of them is worded as one, and every one of them names what happens next and who does it.

System
states

Mobile

Most people arrive on a phone, often late at night. The phone layout is the real one; the desktop layout is the same screen with more air.
